# Adonis iOS 本地 Demo 实施说明

> 状态：本地纵向 Demo 已实现；真机运行与首轮用户测试待完成
>
> 读者：继续开发 Adonis 的工程师与 AI
>
> 阅读后的行动：在不改变产品方向的前提下，运行、验证并继续扩展当前 iOS 本地 Demo。

## 1. 当前目标

第一阶段交付一个中文原生 iOS Demo。它不依赖账号、服务端、付费 API 或公开部署，先验证“一张照片得到值得保存的贴纸作品，并自然成为当天记录”这一核心闭环。当前工程已在 iOS 模拟器完成核心 UI 链路回归，并通过通用 iOS 真机构建；实际 iPhone 运行仍待设备重新连接后验证。

整个产品仍按纵向切片逐步实现，不等待所有衣橱、试穿、风格和长期收藏能力一次性完成后才验证。

## 2. 已确认的产品决定

- 首发平台为 iOS 原生，其他平台以后再考虑。
- 第一版只提供简体中文。
- 首次打开默认展示贴纸收藏卡，不在上传前要求用户选择功能。
- 用户无需注册或登录，Adonis 只使用本地 App 存储，不做账号云同步；iOS 系统设备备份由用户的系统设置控制。
- 当前不接入付费 API，不部署到网络，不考虑商业化。
- 主导航为“创作 / 衣橱 / 花历”。
- 默认分享卡展示日期、Bloom 编号、克制的 Adonis 品牌信息；透明贴纸本体不加水印。
- 结构检查正常时默认直接展示收藏卡；建议复查时默认打开透明贴纸。结果页与历史详情都可在收藏卡、透明贴纸和原始照片间切换，并在结果之后解释当前图片来源，不增加上传前问题。
- 衣橱支持商品图、截图、平铺图、从 OOTD 继续添加，以及从其他 App 分享最多 5 张图片；购物链接解析以后再做。
- 贴纸稳定后再进入单件试穿与三种精选风格，不向普通用户展示 Prompt、Skill 或模型概念。
- 当前本地 Demo 不实现年龄审核和内容审核。任何公开测试或联网处理开始前，必须重新确定相关政策。

## 3. 第一阶段可用闭环

### 创作

1. 用户从相册选择、拍摄或选用内置测试照片。
2. App 在本机识别人像并生成真实透明通道。
3. 程序沿人物轮廓生成连续的纯白贴纸边，不重绘脸、身体、衣物或配饰。
4. App 检查透明区域、主体连通性和纯白边；明显破损时停止，边缘可疑时先让用户查看透明贴纸。
5. App 同时生成透明贴纸和轻松贴纸风格的分享收藏卡。
6. 结果页把透明贴纸标为“原图处理”、收藏卡标为“程序排版”、用户照片标为“原始图片”；当前三者都不含 AI 生成像素。
7. 正常结果不增加质量提示；可疑结果允许直接“这样也收藏”或“再做一张”，不显示分数。
8. 用户可以保存、调用系统分享或重新选择照片。

### 记录今天

用户在看到结果后，可以一次点击保存为今天的 OOTD。原图、贴纸、收藏卡、日期和 Bloom 编号作为同一条记录保存在本机；用户可以查看并删除它。画面信息足够时，记录还会带有上身与下身的临时衣物线索，但它们不会自动变成正式衣橱单品。

### 衣橱

用户可以上传商品图、截图或自己拍摄的衣物照片。App 在本机提取主色、判断画面是否像干净商品图，并在 iPhone 上尽力获取通用类别建议；只有高置信度类别会自动采用，其余保持未分类。图片会直接保存，不要求用户先填写资料，分类不对时可点一下修正。

颜色、画面类型与未确认分类统一显示为“识别建议”，明确说明它来自本机分析且等待用户确认；用户手动选择的分类始终优先。

用户还可以在购物、相册或其他支持系统分享的 App 中选择商品图或截图，再点“Adonis”。分享扩展一次接收最多 5 张图片并写入本机共享收件箱；回到 Adonis 后，主 App 自动分析、去重、入库并展示一条轻量结果提示。用户不需要复制链接、打开导入页或填写资料。

打开一条 OOTD 时，用户还可以处理临时衣物线索：从最多 3 个本地候选中点击“就是它”，点击“这是新衣服”，或“先不管”。候选仅来自类别、颜色和来源元数据，不代表已经识别出同一件衣服；当前没有身份级证据，因此不会自动关联。

用户明确点击“这是新衣服”后，可以继续补一张更清楚的商品图或平铺图，也可以跳过。补图会更新刚才创建的同一件衣服，不再新增单品；用户以后也能从该衣物详情继续补图或换图。

如果用户先保存了 OOTD、后来才加入商品图或平铺图，衣物详情会在确有候选时轻量询问“过去是不是也穿过它？”。候选最多 3 条，只使用本机类别、颜色与来源元数据；点击“是这件”才回填关系，点击“不是它”后不再向当前衣物重复提问。没有候选时整块隐藏，不制造新的整理任务。

### 花历

花历按日期展示已经保存的 OOTD，并提供最小历史浏览。打开记录后仍可切换收藏卡、透明贴纸和原始照片，来源说明与首次结果保持一致，系统分享当前选中的图片。它首先证明长期收藏关系，不在当前阶段加入提醒、连续打卡压力或复杂的植物生长动画。

### 本地数据控制

用户从创作页右上角进入本地设置，可以查看本机内容数量、导出包含原图和记录的标准 TAR，或经二次确认清空所有本地数据。该能力保持在低频入口，不增加主导航，也不要求先建立账号。

## 4. 本地技术边界

- UI 使用 SwiftUI，数据使用 SwiftData 保存在设备上。
- 图片选择使用系统照片选择器；主体分割使用 Apple Vision；白边与透明 PNG 使用 Core Image 和程序化图像处理。
- 分享卡由程序排版，模型不负责生成日期、编号或品牌文字。
- 图片文件保存在 App 沙盒中，直到用户主动删除 App 数据或对应记录。
- 分享扩展与主 App 使用同一个 App Group 图片收件箱交接，不读取网页正文或商品链接；共享文件使用原子写入与文件保护。
- 分享收件箱除单图 40 MB、最长边 16384 像素、总像素不超过 6000 万和单次 5 张外，还限制为最多 50 张、合计 250 MB，避免异常图片在完整解码或持续积压时过度占用设备资源。
- 主 App 只在图片成功入库或确认与已有图片完全相同时移除收件箱文件；失败项继续留在本机，可从提示条重试。
- 当前没有网络请求、用户账号、远程日志、训练数据上传或第三方分析 SDK。
- 本地数据导出按块写入临时标准 TAR，再交给 iOS 系统分享面板；Adonis 不自动选择目的地或上传，临时归档会在分享结束或下次打开设置时清理。
- 导出清单的 `visualAssets` 为每个图片路径保存角色、来源类型、说明、是否包含 AI 生成像素和是否需要用户确认；贴纸与收藏卡还保存结构质量级别、问题代码和检查版本。当前导出的所有视觉资产都不含 AI 生成像素。
- “清空所有本地数据”同时删除 SwiftData、沙盒媒体、App Group 待导入图片和临时 TAR；部分文件清理失败时会明确提示重试。
- 图片、共享文件与临时归档使用 iOS 文件保护。Adonis 不实现账号云同步，但不能替用户控制 iOS 的系统设备备份。
- 只记录不含原图内容的本地事件，例如处理成功、失败、保存和删除，用于 Demo 调试页。
- 衣橱导入保存主色、背景类型、图片尺寸、内容指纹和处理版本；内容指纹只用于阻止完全相同的图片重复入库，不写入调试事件。
- OOTD 衣物线索与正式衣橱单品分开保存；线索随穿搭记录级联删除，只有用户明确点击“这是新衣服”才会创建衣橱单品。
- OOTD 单品补图保留最初建档来源，并把当前图片来源更新为商品图或平铺图。事务先保存新图片和原单品变更，再删除旧图片；失败时保留旧图。
- 补图只刷新自动生成的颜色名称。人工名称、备注和已确认分类优先于新的图片分类建议；已经属于另一单品的重复图片不会被自动合并。
- 衣橱历史回填只扫描 `pending`、未关联且未针对当前衣物排除的 OOTD 线索，最多给出 3 条候选；关系只由用户明确确认，排除结果按衣物持久保存。
- 已确认穿着次数按本地自然日去重显示；确认错误可从对应花历记录撤销并排除原候选。

### 模拟器兼容边界

当前机器上的 iOS 26.5 模拟器无法为任何受测 Vision 推理请求创建推理上下文；人像分割、显著性、人脸框和人体框均失败，在全新模拟器实例与本地签名构建中结果相同。这是模拟器机器学习运行时边界，不应通过伪造蒙版掩盖。

- 真机目标仍使用实时 Apple Vision 人像分割。
- 四张内置样片在 macOS 主机上通过同一套 Vision、Core Image 与白边算法预处理为真实透明 PNG；生成脚本为 `scripts/generate_sample_stickers.swift`，结果可重复生成和检查。
- 四张样片的授权类型、输入与输出哈希、尺寸、像素指标、覆盖标签和已知缺陷保存在 `regression-baseline.json`；`make sample-regression` 会在临时目录重新生成并要求结果逐字节一致，再执行 iOS 像素、结构质量和收藏卡测试。
- 模拟器使用内置样片时走完整的收藏卡、保存、分享与花历流程。
- 模拟器选择自己的照片时，如果 Vision 运行时不可用，会给出明确中文说明，并建议先使用样片或改在 iPhone 上运行；不会展示伪造成功结果。

## 5. 视觉方向

整体气质应轻松、有贴纸收藏感，不使用厚重的希腊神庙或雕塑堆砌。Adonis 的植物、季节和再次盛开精神可以通过小花、嫩叶、手绘线条、日期与 Bloom 编号进入界面。

默认色彩使用温暖浅底、近黑文字、石榴红、嫩叶绿和少量黄油色。圆角、阴影和动效应克制；所有主要触控区域至少为 44 × 44 点，并尊重系统的“减弱动态效果”设置。

当前可暂用“让每一个你，重新盛开”作为 Slogan，不把它视为最终品牌定稿。

## 6. 测试素材规则

项目可以包含用户在本次开发中明确提供的四张照片及其可重复生成的透明贴纸结果，用于本地样片入口和回归测试。外部社交平台页面只能用于理解 OOTD 内容语境；没有明确授权的第三方照片不得复制进项目或发布包。

后续增加测试素材时，应覆盖浅色与深色衣物、全身与半身、复杂头发、手持物、遮挡和多人干扰，并记录素材授权来源。

任何模型、提示、Vision 请求、蒙版、裁切、白边、缩放或收藏卡后处理变化，都必须先运行 `make sample-regression`。候选输出不得直接覆盖固定贴纸；先在临时目录生成并逐张对照原图目检，再有意更新清单中的哈希、指标和已知缺陷。固定集包含一个会把浅色软垫并入主体的坐姿困难样本，不能通过删除失败案例来提高表面通过率。

## 7. 第一阶段验收状态

当前已通过：

- 工程可在当前 Xcode 中完成 iOS 模拟器构建、启动与通用 iOS 真机构建。
- 用户无需登录即可用内置样片完成贴纸与收藏卡、收藏今天、系统分享入口和花历回看。
- 四张贴纸 PNG 均具有真实 Alpha 通道，透明区域超过回归门槛，人物像素来自原照片，长边达到 1536 像素。
- 四张原图和贴纸的仓库哈希、macOS Vision 字节级重生成、解码后像素结构与四张收藏卡已进入一条可重复运行的固定样片门禁。
- 收藏卡固定输出为 1080 × 1440，并且所有像素不透明。
- 结果页和花历详情可以切换收藏卡、透明贴纸与原始照片，并准确显示“程序排版 / 原图处理 / 原始图片”；分享收藏卡本身包含克制的来源声明。
- OOTD、衣橱和调试事件均使用本地 SwiftData 与沙盒图片文件；保存失败会回滚已经写入的文件。
- 衣橱具备添加、查看、编辑分类和删除本地单品的基础链路。
- 衣橱具备本机主色与白底商品图判断、低置信度保护、完全相同图片复用和一次点击分类纠正。
- 衣橱分析与 OOTD 衣物线索明确显示为待确认的“识别建议”，不把本机推测伪装成事实。
- 系统分享面板可把具体 PNG 图片交给 Adonis 分享扩展，并跨 App Group 边界自动进入主 App 衣橱；一次最多 5 张，失败可重试。
- OOTD 具备上身与下身临时线索、最多 3 个本地候选，以及“就是它 / 不是这件 / 这是新衣服 / 先不管”的轻量确认；保存线索本身不会增加衣橱单品。
- 从 OOTD 明确创建的单品可补商品图并原地升级；人工信息不被覆盖，重复图不自动合并，更新后衣橱单品总数不变。
- 后来加入商品图或平铺图后，衣物详情可反向提示最多 3 条尚未处理的历史 OOTD，并完成明确确认、持久排除、按天汇总和花历撤销；不会自动关联。
- 本地设置可查看个人数据数量、生成可被标准系统工具读取的 TAR，并把数据库、媒体、共享收件箱与临时导出全部清空。
- 处理状态具备中文进度、取消、失败说明和重新选择入口。
- 贴纸结构质量状态已贯穿结果、收藏、花历、本地事件与个人数据导出；第 4 张困难样片稳定进入“建议复查”，前三张不出现多余提示。
- 本地调试信息不记录或外传图片内容。

仍待通过：

- 使用更多授权素材检查头发、透明材质、多人、严重遮挡和手持物边缘。

## 8. 后续阶段

1. 使用更多授权照片和真实用户验证贴纸边缘与首次流程。
2. 单独验证不同购物平台可分享的商品链接与数据范围；图片或截图分享已经可用，但当前不抓取页面或解析链接。
3. 建立授权的商品图与同款 OOTD 对照集，验证哪些视觉或商品身份信号足以改善候选质量并支持未来的可靠自动匹配；当前历史回填已经可由用户明确确认，未证明前继续禁止自动关联。
4. 在明确数据告知和成本边界后，比较可替换的第三方试穿与创作供应方案。
5. 上线单件试穿与三种精选风格。
6. 验证花历、再次盛开和长期收藏是否真正带来回访。
7. 只有在本地闭环验证后，再决定账号、联网、公开部署、内容政策与商业化。
