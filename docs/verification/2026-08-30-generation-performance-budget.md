# 2026-08-30 生成性能与预算验证

> 当前结论（2026-08-31 更新）：ADO-Q05 的记录骨架已扩展到默认 AI 贴纸。`generation-performance-v2` 记录 AI 贴纸生成及后续阶段、45 秒目标、中断位置、重试和 provider 执行元数据。默认贴纸调用 Apple 系统 `ImageCreator`：provider 请求为 1、外部请求数未知、网络为系统托管、费用未公开，不能再把主链路写成全本机或 0 外部请求。下文 2026-08-30 的全本机数字是历史直抠样片基线；现行证据见 [AI 贴纸先生成后抠图验证记录](2026-08-31-ai-sticker-first-pipeline.md)。真实 Apple 成本、网络、重试和真机时延尚未证明，所以 ADO-Q05 保持未完成。

## 1. 计时口径

计时使用单调递增的 `ContinuousClock`，不受系统时间调整影响。相册链路从照片选择器交回项目并开始读取数据时计时，包含数据传输和图片解码；相机链路从系统相机交回图片后计时，不把用户取景与按快门的时间算作处理；内置样片从生成任务开始计时。

终点是以下任一状态：

- 收藏卡、结构检查和衣物线索全部完成，可以展示结果；
- 读取、抠图、检查或后处理失败；
- 处理达到 90 秒用户等待上限；
- 用户点击“取消”，迟到结果随后会被当前生成 ID 隔离。

总耗时包含阶段切换和少量调度开销，因此不要求各阶段相加与总耗时逐毫秒完全相等。

| 阶段 | 记录范围 | 特殊边界 |
| --- | --- | --- |
| `inputLoading` | 相册数据读取与 `UIImage` 解码 | 相机回调和内置样片没有这一段 |
| `aiStickerGeneration` | Apple 系统生成不透明贴纸源 | provider 请求为 1；外部请求数、网络细节与费用由系统管理 |
| `subjectExtraction` | Vision 主体分割、透明裁切与纯白贴纸边 | 内置样片复用预处理贴纸，仍标记 `usesPreparedSample = true`，不能代表实时 Vision |
| `qualityAssessment` | 透明度、主体连通与白边结构检查 | 只判断结构事实，不代表人物或衣物语义保真 |
| `shareCardComposition` | 1080 × 1440 收藏卡程序排版 | 不新增 AI 像素，但输入为 AI 贴纸时成品继承 AI 来源 |
| `garmentObservation` | 可信直抠链路的上身与下身临时衣物线索 | 默认 AI 贴纸主链路跳过该事实推断 |

当前性能契约版本为 `generation-performance-v2`，第一张最终结果的测量目标为 45,000 毫秒。45 秒来自产品规格，只用于测量是否达到目标，不是供应商 SLA。独立的 90 秒截止会强制界面退出等待并隔离迟到结果；它不代表底层 Apple 生成或 Vision 一定立即停止。完整边界见 [生成超时与基础贴纸降级验证记录](2026-08-30-generation-timeout-fallback.md)。

## 2. 终态、持久化与隐私

- `GenerationPerformanceRecorder` 串行记录阶段，首次生成终态后冻结；后续迟到调用不能改写已保存的结果。
- 成功保存完整阶段；失败、超时和取消把正在进行的阶段按已消耗时间收口，并保存 `interruptedStage`。
- `AppEvent` 使用可查询的可选字段保存性能版本、目标、AI 生成与后续阶段耗时、重试、执行元数据、样片标记和中断阶段。旧事件没有这些字段时仍可读取，不伪造历史性能。
- 结构化性能总耗时是事件 `durationMilliseconds` 的权威来源，避免调用方同时传入两个不同数字。
- 事件落库不再使用静默的 `try?`。失败时只写入事件类型、错误域和错误码到本机系统日志，不记录图片、文件路径、提示词或用户内容。
- 个人数据导出当前为 `adonis-personal-data-v8`。`processingEvents.generationPerformance` 保存版本、总耗时、目标、预算状态、阶段字典、最慢与中断阶段、重试、样片标记和 provider 执行元数据；`outfits.generationCompletionMode` 独立保存完整结果或同一 AI 链路中的可交付降级。

## 3. 用户入口

日常创作流程没有增加选择或技术术语。“本地设置 → 处理状态”展示：

- 成功、失败、超时和取消次数；
- 成功结果的平均端到端耗时，以及多少次落在 45 秒目标内；
- 最近一次终态、耗时、最慢阶段和可用时的中断位置；
- 本地重试、外部请求和外部费用状态；
- 最近一次使用内置样片时，明确提示它只代表本机演示链路。

升级前的旧成功事件只有局部处理耗时，或只有 `generation-performance-v1` 结构；它们仍可在事件列表中查看，但不伪造 v2 的 AI 阶段与 provider 元数据。

当前设置页按最近记录动态显示：历史直抠样片可以是“外部请求 0 次 / 费用不适用”；默认 AI 贴纸显示 Apple provider 请求 1 次、外部请求未知、网络系统托管、费用未公开。不得把未知改写为 0。

## 4. 专项自动验证

专项命令：

```bash
make performance-regression
```

它覆盖：

- 成功事件的结构化落库和总耗时唯一来源；
- 失败事件的部分阶段、中断位置、重试与可用执行元数据；
- 可控时钟下的阶段顺序、目标内与超目标结果、负值保护和终态冻结；
- `adonis-personal-data-v8` TAR 中可由系统工具读取的性能结构、AI provider 元数据与结果完成模式；
- 内置样片完成后设置页显示 45 秒目标、最近终态、最慢阶段和本机费用边界；
- 用户取消后设置页显示“取消处理”和“抠图与白边”中断位置；
- 无可用中间产物的超时退出等待、提供恢复动作并隔离迟到结果；
- 有合格贴纸与收藏卡的超时只交付同一次 AI 链路结果，并把说明与 AI 来源保留到花历。

最终专项结果为 13 个单元测试与 4 个 UI 流程测试，共 17 项通过、0 失败、0 跳过。`xcresulttool` 独立汇总一致；结果包为 `.derivedData/Logs/Test/Test-Adonis-2026.08.30_04-03-20-+0800.xcresult`。

当前完整门禁为 127 个单元测试与 28 个 UI 流程测试，共 155 项通过、0 失败、0 跳过；结果包为 `.derivedData/Logs/Test/Test-Adonis-2026.08.30_11-55-11-+0800.xcresult`。

## 6. 尚未证明

- 内置样片跳过实时 Vision，因此 287 毫秒不能代表用户相册照片或真实 iPhone 的完整抠图速度。
- iOS 模拟器当前不能执行受测 Vision 推理；尚未获得真实 iPhone 上不同分辨率、温度、低电量和内存压力下的 P50、P95 或 P99。
- 当前没有云端模型、第三方供应商、鉴权、网络请求或计价，所以没有可记录的供应商延迟、单次价格、重试、限流、幂等和失败成本。
- 45 秒仍只是测量目标。90 秒用户等待边界、基础贴纸降级和迟到结果隔离已经实现，但底层 Vision 在超时或取消后不保证立即停止。
- App 进程在处理中被系统直接终止时，只会留下已经持久化的“开始处理”事件，无法在进程死亡后补写终态。
- 尚未建立持续的性能基线趋势、内存峰值、能耗与热状态门禁。

因此这份记录可以作为后续计时、预算、处理事件、设置诊断与导出字段的本地回归契约，但不能据此勾选 ADO-Q05、ADO-108 或真实供应商验证。ADO-Q04 的本机超时切片已完成，联网供应商不可用与重试仍待真实接入后验证。
