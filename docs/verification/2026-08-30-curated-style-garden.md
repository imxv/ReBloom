# 2026-08-30 精选风格花园验证

> 结论：Adonis 已把 Apple 系统图片生成整理成一个低心智入口“风格花园”。用户不需要理解 Prompt、Skill、模型、工作流或参数，只需在三个经过产品命名的方向中选一个：永生花园、花神速写或月光剧场。三种结果都支持停止等待、90 秒超时、原图对照、明确来源、收藏、系统分享和跨进程历史回看。
>
> 当前证据只证明产品交互、系统 API 适配、执行记录和本地数据链路。iOS 模拟器中的成功画面来自仅 Debug 的确定性抽象夹具，不是 Apple `ImageCreator` 的真实输出。它不能证明风格稳定、身份或衣物保真、真实时延、网络行为、费用，也不能证明用户愿意保存或分享。

## 1. 产品契约

- 贴纸结果页只有一个“风格花园”入口，不为每种风格堆叠独立入口。
- 入口只在 Apple 系统图片生成能力可用时出现；广义能力不可用时整体隐藏，不留下不可点击的功能广告。
- 选择页固定显示三个结果方向和一句用户能理解的效果说明，不展示技术名词、自由文本输入或高级设置。
- 用户选择前会看到“每种风格都会重新绘制人物、衣服和背景”；这些结果不是保真滤镜、虚拟试穿或真实新照片。
- 结果固定标为“AI 生成”，并可在作品与原始照片之间切换。只有用户明确点击收藏才持久化作品。

这个入口服务的是“看到一个喜欢的感觉，点一下得到自己的版本”，不是让用户配置生成工具。

## 2. 第一批三种配方

| 用户名称 | 用户看到的感觉 | 系统样式 | 版本 |
| --- | --- | --- | --- |
| 永生花园 | 石榴花、常青叶与深酒红色的植物神话插画 | illustration | `mythic-garden-v1` |
| 花神速写 | 暖纸、铅笔与彩铅质感的时装手稿 | sketch | `floral-sketch-v1` |
| 月光剧场 | 钴蓝夜色、花火与温室构成的动画剧照 | animation | `moonlit-theater-v1` |

内部概念只用于向系统表达固定方向，不显示给用户，也不进入事件、数据库或个人数据导出。公开文案只描述结果感受，不能把内部实现包装成可编辑 Prompt 或可调用 Skill。

这三个方向是工程目录，不是已经通过真实输出筛选的正式质量承诺。ADO-304 仍需在支持该能力的真实 iPhone 上，用四张授权固定样本评价后才能完成。

## 3. 系统适配与能力边界

生产实现使用 iOS 18.4+ `ImagePlayground`：

1. 将用户原始照片归一为最长边不超过 2048 像素的不透明输入。
2. 创建 Apple `ImageCreator`，读取当前设备实际可用的样式。
3. 只有所选配方对应的 illustration、sketch 或 animation 可用时才请求一张结果。
4. 将返回画面排成 1080 × 1440 的不透明收藏卡。

系统框架只能在创建 `ImageCreator` 后提供具体样式列表，因此入口使用系统广义能力做前置门控；若某一种样式在当前设备不可用，选择后会得到可恢复的“不支持”结果，原贴纸保持不变。不能为了让三个选项始终可点而用其他样式冒充。

## 4. 执行、隐私与费用口径

三种系统配方使用相同的执行口径：

| 字段 | 保存值 |
| --- | --- |
| `provider` | `apple_image_playground` |
| `providerRequestCount` | `1` |
| `externalRequestCount` | 未向 App 暴露，保存为未知 |
| `networkTransport` | `system_managed` |
| `externalCost` | 未向 App 暴露，保存为 `not_exposed` |
| `quality` | `user_review_required` |

Adonis 没有为这条链路配置第三方图片 API、账号或 API Key，但不能据此声称处理完全离线、没有外部请求或免费。处理和可能的网络传输由 Apple 系统管理，未知字段必须保持未知。

成功、失败、取消和超时事件只记录配方、版本、来源类型、耗时、provider、请求/网络/费用/质量口径和固定错误码，不记录照片、内部概念、文件路径、记录 ID 或用户文字。

## 5. 取消、超时和持久化

- 每次创作使用独立活动 ID、生成任务和 90 秒截止任务。
- 用户停止或超时时，先让当前活动失效，再取消任务；迟到结果不能打开页面、写成功事件或保存作品。
- 失败、取消、超时与具体样式不可用都保留原始照片、透明贴纸和收藏卡。
- 未收藏作品只存在于当前内存；收藏后，PNG、配方版本、处理耗时和执行元数据关联原 OOTD。
- App 终止并重新启动后，用户可从花历中的原 OOTD 打开作品、对照原图并分享。
- 删除原 OOTD 会级联删除作品和媒体；清空本地数据同时覆盖作品、媒体和临时导出。
- `adonis-personal-data-v7` 会分别导出三种系统配方，并把对应视觉资产标为 `ai_generated`。

## 6. Debug 夹具边界

模拟器专项通过 `#if DEBUG` 的确定性夹具覆盖能力可用、不可用、成功、永不完成、取消和超时。三种风格使用不同的抽象色板，以便验证选择与历史记录没有串配方。

这些夹具只用于证明：

- 一个入口与三个选项的交互；
- 所选名称贯穿处理中、结果、收藏和历史；
- AI 来源、整图重绘边界与原图对照；
- 系统分享、跨进程回看、取消和超时；
- 执行元数据、个人数据导出与完整清理。

夹具不能进入 Release，不能用于评价 Apple 模型输出，也不能作为产品宣传样片。来自该路径的截图必须明确标为“Debug 夹具”。


- 三种配方的稳定顺序、公开文案与系统样式映射；
- 三种 1080 × 1440、不透明收藏卡；
- 一个风格花园入口、三个选项与能力不可用时整体隐藏；

## 8. 尚未证明

- 尚未在支持该能力的真实 iPhone 上生成并保存三种 Apple 真实输出。
- 尚未用四张授权固定样本比较风格稳定性、脸部一致性、身体比例、姿势和衣物细节变化。
- 尚未验证 illustration、sketch 与 animation 在不同机型、系统语言和地区是否都可用。
- 尚未验证真实处理时延、系统资源下载、弱网、飞行模式、系统级取消响应或费用表现。
- 尚未完成真实 VoiceOver、系统分享目的地、前后台/锁屏中断和整机重启验证。
- 尚未证明三个名称与预览能让首批用户无讲解理解，也未证明结果值得保存、分享或再次打开 Adonis。

因此，当前可以把风格花园视为“低心智、多配方、可追溯的系统创作骨架”，不能把它描述成“已上线稳定的三种强风格生成”。
