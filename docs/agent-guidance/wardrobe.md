# wardrobe

只读取本次涉及的条目与其链接。既有验证记录的设备、日期和证据范围仍适用；不要求把所有历史记录全文读一遍。

涉及衣橱导入、图片分析或类别策略时，参考 [衣橱轻量导入验证记录](../verification/2026-08-29-wardrobe-import.md)，尤其是“尚未证明”部分。

涉及系统分享扩展、App Group 收件箱或从其他 App 导入衣橱图片的流程时，参考 [购物应用图片分享验证记录](../verification/2026-08-29-shopping-app-image-share.md)。当前只接收图片附件，最多 5 张；不得把它描述成商品页面抓取或商品链接解析。

涉及数字展柜的排序、花历入口、贴纸展位、OOTD 跳转、衣橱关系摘要、空态或能力边界时，参考 [数字展柜验证记录](../verification/2026-08-30-digital-cabinet.md)。相关验证命令见 verification.md，按实际受影响行为选择。展柜只从已收藏 OOTD 自动派生，不保存第二份手办资产；只有用户明确确认过且当前仍存在的衣橱关系才能显示为“已确认”，待确认与已移除关系不得被补成事实。

涉及 OOTD 衣物发现、视觉签名、候选排序、旧数据回填、自动关联或历史回填时，参考 [OOTD 衣物线索与确认验证记录](../verification/2026-08-29-ootd-garment-observations.md)与 [衣橱视觉线索排序验证记录](../verification/2026-08-30-wardrobe-visual-matching.md)。相关验证命令见 verification.md，按实际受影响行为选择。当前类别、颜色、来源与视觉分布都只是待确认建议，不是同款识别证据。

涉及 OOTD 单品的商品图补充、图片替换、重复判断或历史回填时，参考 [OOTD 单品补商品图验证记录](../verification/2026-08-29-ootd-product-image-upgrade.md)。补图必须原地升级同一个衣物实体，保留用户命名、备注与已确认分类；重复图片不得在没有用户确认的情况下自动合并两个单品。

涉及衣橱历史穿着回填、候选排除或关系撤销时，参考 [衣橱历史穿着回填验证记录](../verification/2026-08-29-wardrobe-history-backfill.md)。当前反向查找只提供最多 3 条画面相似候选，必须由用户明确确认；不得描述成同款识别或自动回填。

- 衣橱应随 OOTD、商品图和分享行为自然形成，而不是成为录入任务。

- 没有商品 SKU、可靠视觉身份特征或经固定对照集验证的等价证据时，不得自动把 OOTD 线索关联为已有衣物；候选最多展示 3 个，只有用户明确确认后才能改变衣橱关系。

- 历史回填只处理尚未决定、尚未关联且未针对当前衣物排除的 OOTD 线索；“先不管”和“不是它”必须被长期尊重，确认错了仍可从花历撤销。

- 用户为已经明确创建的 OOTD 单品补图时，先写入新图并保存实体，再删除旧图；任何失败都必须保留旧图与原单品。AI 建议不得覆盖人工名称、备注或已确认分类。

- “再次盛开”只在至少一件上装和一件下装都有显式确认来源、仍存在于衣橱且从未共同确认时出现；优先最久未穿单品与最近熟悉底座。未纠正的 OOTD 自动颜色名只能降级为“这件上装 / 这件下装”，补商品图或人工名称优先。结果按需派生且不保存第二份资产，分享卡必须标明本机组合建议与非试穿效果。
